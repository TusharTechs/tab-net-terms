# Full demo run (2026-11-10, run `rmwan72qu`)

`LIVE_VIC=1 npx tsx scripts/demo-run.ts` plays every scene into `data/desk-demo.json`; the demo screen (`npm run screen`) streams them and `npm run replay` turns the run into the no-login replay page (`docs/index.html`). Live: Metal testnet, Claude (`claude-opus-5-5`: CFO policy compiler, two buyer agents, dispute reader), Visa Intelligent Commerce via Airi (one passkey approval), Airwallex sandbox, T:0 sandbox. **19/19 checks pass.**

What is labelled rather than live:
- **Globex's and Initech's books** are the stand-in (`fixtures/standin-books.json`): Globex has no history with Northwind; Initech has INV-3002 ($400) overdue. T:0 has no matching customers and this key can read records and post journal entries but cannot create records (`403 CAPI72`). Acme's books are real T:0 sandbox records.
- **Airwallex deposits** are sandbox simulations (the sandbox cannot receive stablecoins); quotes, conversions and card payments are real sandbox calls.
- **Due dates are compressed**: Acme's statement mandate opens about 75 s after issue and closes 5 min later; Globex's 7-day card tab is captured seconds after its credit note.
- **Stale units are set by the script** (Acme: 10% of the disputed order flagged by delivery QA; Globex: one 1,000-row batch). The model reads the email; credits come from the QA count, never from the email's "all units".
- **Globex's card is the same Airi test card** Acme used on 2026-11-09 (one card is enrolled).
- **Initech** has no Metal account or mandate (placeholder address); it shows the books and orders for terms it is not offered being refused.
- **Acme's testnet balance** was $304.05 (the faucet's daily limit stopped a second top-up), so its credit limit is capped by its balance rather than the CFO's $350 cap.
- **The buyers' owner keys** that bind mandates are key files run by the demo script, standing in for each buyer's human.
