# Full demo run (2026-11-10, run `rmwalbcax`)

`LIVE_VIC=1 npx tsx scripts/demo-run.ts` plays every scene into `data/desk-demo.json`; the demo screen (`npm run screen`) streams them. Live: Metal testnet, Claude (`claude-opus-5-5`: CFO policy compiler, two buyer agents, dispute reader), Visa Intelligent Commerce via Airi (one passkey approval), Airwallex sandbox, T:0 sandbox. **19/19 checks pass.**

What is labelled rather than live:
- **Globex's and Initech's books** are the stand-in (`fixtures/standin-books.json`): Globex has paid 3 invoices on time, Initech has INV-3002 ($400) overdue. T:0 has no matching customers and this key can read records and post journal entries but cannot create records (`403 CAPI72`). Acme's books are real T:0 records.
- **Airwallex deposits** are sandbox simulations (the sandbox cannot receive stablecoins); quotes and conversions are real sandbox calls.
- **Due dates are compressed**: Acme's statement mandate opens about 75 s after issue and closes 5 min later; Globex's 7-day card tab is captured a few seconds after its credit note.
- **Stale units are set by the script** (Acme: 10% of the disputed order flagged by delivery QA; Globex: one 1,000-row batch). The model reads the email; credits come from the QA count, never from the email's "all units".
- **Globex's card is the same Airi test card** Acme used on 2026-11-09 (one card is enrolled).
- **Initech** has no Metal account or mandate (placeholder address); it shows the books and a scripted attacker being refused.
- **Acme's testnet balance** was raised above the faucet's 100 USDZ ceiling with `scripts/top-up-buyer.ts` (helper pulls `0x54a32598…2e64`, `0x65dacb66…4129` before this run).

- The applied policy's hash matches its content and its signature verifies under Northwind's public key; it holds `requireVicBeforeCredit: true`.

**Bug this run exposed (fixed after it, not re-run):** the dispute credit was priced at list (200 × 4¢ = $8.00) although Acme was charged 3% less, so it should have been 200 × 3.88¢ = **$7.76**: a 24¢ over-credit to the buyer. Credits are now priced at what the order was actually charged (`test/decide.test.ts`). The books still balance in this run because the credit was applied consistently.

**Log wording fixed after this run:** the refusal of the edited policy printed the hash the CFO signed (`0x56f3af7c…`), not the hash of the edited content it actually received, so the refused and applied lines show the same hash. The refusal itself was correct (the content no longer matched the signed hash); the message now shows both hashes.
