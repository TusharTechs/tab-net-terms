# Full demo run (2026-11-10, run `rmwavgb3a`)

`LIVE_VIC=1 npx tsx scripts/demo-run.ts` plays every scene into `data/desk-demo.json`; the demo screen (`npm run screen`) streams them and `npm run replay` turns the run into the no-login replay page (`docs/index.html`). Live: Metal testnet, Claude (`claude-opus-5-5`: CFO policy compiler, two buyer agents, dispute reader), Visa Intelligent Commerce via Airi (one passkey approval), Airwallex sandbox, T:0 sandbox. **21/21 checks pass.**

What is labelled rather than live:
- **Globex's and Initech's books** are the stand-in (`fixtures/standin-books.json`): Globex has no history with Northwind; Initech has INV-3002 ($400) overdue. T:0 has no matching customers and this key can read records and post journal entries but cannot create records (`403 CAPI72`). Acme's books are real T:0 sandbox records.
- **Airwallex deposits** are sandbox simulations (the sandbox cannot receive stablecoins); quotes, conversions and card payments are real sandbox calls.
- **Due dates are compressed**: Acme's statement mandate opens about 75 s after issue and closes 5 min later; Globex's 7-day card tab is captured seconds after its credit note.
- **Stale units are set by the script** (Acme: 10% of the disputed order flagged by delivery QA; Globex: one 1,000-row batch). The model reads the email; credits come from the QA count, never from the email's "all units".
- **Globex's card is the same Airi test card** Acme used on 2026-11-09 (one card is enrolled).
- **Initech** has no Metal account or mandate (placeholder address); it shows the books and orders for terms it is not offered being refused.
- **Acme's testnet balance** was $261.55 (above the faucet's 100 USDZ ceiling via `scripts/top-up-buyer.ts`, helper pulls `0xf69f9f3b…c83ed` and `0xd4346da6…08f7f`), so its credit limit is capped by its balance rather than the CFO's first $350 cap.
- **The buyers' owner keys** that bind mandates are key files run by the demo script, standing in for each buyer's human. The CFO's policy key is likewise a key file the script signs with.

## Live fault: kill the desk mid-pull on the credit line

Run on a copy of this run's state (`data/desk-faults.json`, screen started with `ALLOW_FAULTS=1`), after Acme's balance was topped up to $150.06 (helper pull `0x94d53e14…40cb`):

1. A $20.00 order (500 market-data queries, net-30) went on Acme's tab, and Acme asked to pay now.
2. The desk recorded the pull as in flight (with the mandate's spent total), sent it to Metal, and was killed before recording Metal's answer.
3. A statement drafted over the same order was refused: the order was in a pull still in flight.
4. A fresh desk restarted from disk, saw the mandate's spent total had risen by the pull, found the transfer on chain and recorded it, **sending nothing again**.

Result: pulls sent **1**; Acme's balance moved **$20.00** ($150.06 → $130.06); the proof re-ran at **21/21**. The collection `0xb6a6361fa19d0f6a32e64e145526bd866d3d946b36ad9cc6779ae5e19f03a355` read back status `0x1` with one transfer log of 20.00 USDZ from Acme to the supplier wallet, and a search of the last ~90 minutes of blocks found no other $20.00 transfer from Acme to Northwind.
